# Function Calling 与工具设计

## 学习目标
手写工具定义、注册和参数校验。完成后能独立解释数据流，并用失败实验验证边界。

## 原理与设计
工具名称与描述用于语义选择，JSON Schema 描述参数类型和必填项；约束生成只能保证部分结构正确性，不能保证业务语义。工具注册保存元数据与函数映射；模型返回调用名、参数和关联 ID。

## 数据流
```text
注册 → 暴露 schema → 模型生成调用 → 校验 → 执行 → 关联结果
```

## 实验与观察
查看 Registry.register 和 call；添加 query_customer 工具；构造不存在的工具、错误类型、缺失字段及额外字段。对真实模型比较模糊描述与明确描述在十条同义请求上的表现。

先预测输出，再运行，记录实际输出与预测差异。修改一个变量后复测，不要只截图成功结果。

## 企业场景
订单查询与退款分开定义，退款必须通过服务端授权和人工确认。

## 验收问题
为什么 schema 合法不代表参数正确？工具调用 ID 有何意义？
