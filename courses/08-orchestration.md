# 规划、工作流与多智能体

## 学习目标
按确定性和自主性选择编排模式。完成后能独立解释数据流，并用失败实验验证边界。

## 原理与设计
固定工作流适合规则明确的流程；Agent 适合需要动态选择路径的任务。ReAct 是推理与行动交替的思想，不要求暴露模型私有推理。规划可生成可验证的步骤；状态机定义合法转换，子智能体只传递必要上下文。

## 数据流
```text
任务 → 规划 → 执行步骤 → 检查 → 修订或结束
```

## 实验与观察
运行 labs/workflow.py；模拟审批拒绝、批准与重复提交，验证没有批准时不能写入。设计一个检索与审阅两个角色的交接 schema。

先预测输出，再运行，记录实际输出与预测差异。修改一个变量后复测，不要只截图成功结果。

## 企业场景
审批流程优先确定性状态机，模型只辅助提取和建议。

## 验收问题
什么时候不需要多 Agent？任务恢复应持久化哪些状态？

用自己的话回答，并提交一条正常测试和一条失败测试；不能解释原因则回到原理部分。
