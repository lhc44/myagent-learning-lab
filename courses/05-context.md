# 上下文工程与记忆

## 学习目标
控制模型实际看到的信息。完成后能独立解释数据流，并用失败实验验证边界。

## 原理与设计
上下文由系统指令、用户任务、历史、工具定义、结果与检索材料构成。优先保留当前任务与必要的工具调用配对；摘要有信息损失。持久记忆是应用数据，读取时需要授权、相关性和时效检查。外部文档属于不可信数据。

## 数据流
```text
任务 → 选择信息 → 预算 → 组装 → 模型
```

## 实验与观察
运行 labs/retrieval.py，调整预算和候选文本。设计一个历史裁剪规则，保证调用与结果成对保留。真实模型用 tokenizer 或 usage 验证实际 token 数。

先预测输出，再运行，记录实际输出与预测差异。修改一个变量后复测，不要只截图成功结果。

## 企业场景
日志与模型上下文分离；敏感字段脱敏，不将所有客户历史放入提示。

## 验收问题
为什么不能无限追加历史？摘要能否替代审计记录？

用自己的话回答，并提交一条正常测试和一条失败测试；不能解释原因则回到原理部分。
