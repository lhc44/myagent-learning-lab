# Agent Harness、Skills、Hooks

## 学习目标
理解现代智能体的支撑系统。完成后能独立解释数据流，并用失败实验验证边界。

## 原理与设计
Harness 是一组工程组件而非统一协议：工具、上下文、运行循环、权限、文件工作区、观察与恢复。Skill 可用说明和资源描述可复用任务；Hook 在特定生命周期触发校验或日志；Plugin 打包能力；Subagent 是受限制的委派执行单元。具体格式随框架不同。

## 数据流
```text
任务 → Harness → 加载技能 → 调用前 hook → 执行 → 调用后 hook
```

## 实验与观察
为 Registry.call 增加 before/after 钩子，记录工具名、耗时、成功状态；添加一个禁止写入的策略并用测试验证。不要把密钥或全文写入日志。

先预测输出，再运行，记录实际输出与预测差异。修改一个变量后复测，不要只截图成功结果。

## 企业场景
企业插件应审查能力声明、依赖、权限与版本。

## 验收问题
Skill 与 Tool 的区别是什么？为什么 hook 不能仅依赖提示词？

用自己的话回答，并提交一条正常测试和一条失败测试；不能解释原因则回到原理部分。
